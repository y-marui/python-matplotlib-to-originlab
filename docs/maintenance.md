# Docs Maintenance

`docs/` ファイルをローカル LLM でメンテナンスするためのプロンプト集。

---

## Updating architecture.md

```
docs/architecture.md の更新案を作成してください。

手順：
1. プロジェクトのディレクトリ構造を確認する（ls -la、各サブディレクトリの __init__.py / app.py 等）
2. 各パッケージのエントリーポイントと主要な依存関係を把握する
3. 既存の docs/architecture.md を読む
4. 以下のフォーマット仕様に沿った更新案を、根拠となるファイルパスとともに出力する（ファイルへの保存はしない）

フォーマット仕様：
- ## Overview: プロジェクト全体像を3行以内
- ## Entry Points: 主要エントリーポイントのパスと説明
- ## Directory Structure: ディレクトリと役割のテーブル
- ## Data Flow: ASCII アートでデータフロー
- ## Key Dependencies: 主要ライブラリと用途のテーブル
- ## Platform Notes: プラットフォーム固有の制約

注意：ファイルレベルの詳細は記載しない（file-map.md に委譲）
```

---

## Updating file-map.md

```
docs/file-map.md の更新案を作成してください。

手順：
1. 今回の作業で参照・編集したファイルを確認する
2. 既存の docs/file-map.md を読む
3. 以下のフォーマット仕様に沿って、未記載ファイルの追記案・既存エントリの更新案を、根拠となるファイルパスとともに出力する（ファイルへの保存はしない。既存エントリを削除する案は出さない）

フォーマット仕様：
- ## [モジュール / 機能名] のセクションごとにテーブルを持つ
- テーブル列: ファイル | 役割 | 主な依存先
- _最終更新_ の日付を今日の日付に更新する

注意：未探索ファイルは記載しない（不正確な記述を避ける）
```

> 上記の出力は更新案であり、主担当 AI が根拠と実ファイルを照合し、確認済みの内容だけを保存する。
